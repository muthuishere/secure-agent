Install

git clone https://github.com/muthuishere/secure-agent && cd secure-agent
task install        # build → ~/.local/bin/sec → link the agent skill → add harness deny rules
sec init

task install also runs sec skill install. Home is ~/.config/sec, override with SEC_HOME (useful for a throwaway vault in a test).

The model

  • Vault — ~/.config/sec/vault/NAME.age (age X25519, filippo.io/age) plus NAME.json metadata. Ciphertext and names only: safe to commit to a private repo or rclone sync. Syncing is not sec's job.
  • Identity — SEC_IDENTITY env > OS keyring > identity.txt (0400). macOS and Windows default to the keyring; Linux, BSD, containers and CI default to the file, because a server has no Secret Service and a desktop one is DBus that can block on an unlock prompt nobody will answer in cron.
  • Owner vs agent — a TTY on stdin, or SEC_OWNER=1, is the owner. get --print, export and --allow-output-only need it. Agent harnesses run with a piped stdin, so they never have it.
  • Redaction — exec and run scrub each value plus its base64 (with and without trailing newline), hex, URL-encoded and JSON-escaped forms from stdout and stderr, line-buffered. Because it is line-buffered, a value split across newlines — e.g. fold -w 12, or an xxd dump wrapped at 60 columns — is not scrubbed. It defends against accidental echo, not against a program written to smuggle the value out.
  • Placement ledger — env write, render, import, gen --env and place all record where a value went; rotate replays them.
  • Audit — ~/.config/sec/audit.ndjson: action, names, agent, cwd, template. Never values.

sec init

Create the age identity and an empty vault.

  --backend keyring|file      where to keep the key (default: keyring if the OS store answers)
  --import-identity FILE      adopt an existing age identity instead of generating one

sec set

Store a value from stdin — a masked prompt on a TTY, raw stdin from a pipe or heredoc. The value never touches argv.

  --source URL|note   where this is minted/revoked — used by rotate
  --tag a,b           comma-separated tags
  --raw               keep the trailing newline (PEM / JSON material)
  --place             after storing, re-apply to every recorded placement

printf '%s' "$VALUE" | sec set STRIPE_KEY --source https://dashboard.stripe.com/apikeys

If the value arrived through an agent, sec says so and suggests rotating once the real source can mint a fresh one.

sec gen

Generate a password or token straight into the vault and/or a dotenv file. It is never displayed.

  --save NAME      store as this secret
  --len N          length in chars, or bytes with --hex (default 32)
  --hex            hex token of --len random bytes
  --no-symbols     letters and digits only
  --env FILE=VAR   also write to a dotenv file (repeatable via comma)
  --tag a,b        tags for --save
  --print          owner-only: print instead

sec gen --save APP_DB_PW --len 32 --env infra/vault/dev/.env.dev=DB_PASSWORD

sec exec

Run a command or script with {{NAME}} placeholders filled; output scrubbed. This is the verb for anything that takes a credential as an argument or inside a body.

  -f FILE                 script/template to render and execute (args after -- go to it)
  --allow-output-only     owner-only: permit echo/cat/env style commands

sec exec -- curl -H "Authorization: Bearer {{STRIPE_KEY}}" https://api.stripe.com/v1/balance

sec run

Run a command with secrets injected as environment variables; output scrubbed.

sec run NAME[,NAME2][=ENVVAR] -- cmd args…

sec run APP_DB_PW=DB_PASSWORD -- ./migrate up

sec render

Fill a template file with secrets → a 0600 output file; the placement is recorded.

  --out PATH       output path (0600)

sec render conf.tmpl --out conf.yaml
✓ rendered conf.tmpl → conf.yaml (0600; 2 secret(s), placement recorded)

sec env

Write dotenv files without reading them.

sec env write FILE NAME[=VAR]…      # add/replace keys, 0600, recorded as a placement
sec env ls FILE                     # list the keys in a dotenv file (names only)

sec import

Import every KEY=value of an existing dotenv into the vault. The file itself becomes a placement, so a later rotate updates it.

  --only a,b     comma-separated keys (default all)
  --tag a,b      tags for every imported secret
  --no-place     do not record the file as a placement

sec export

Owner-only. Write chosen secrets to a .env file in plaintext.

  --confirm      required: this writes plaintext values
  --only a,b     comma-separated names (default all)
  --out PATH     output .env path (0600)

sec place

Record where a secret lives — and push the value there now.

  --file PATH[=VAR]                          dotenv placement
  --gh owner/repo[:environment][=SECRET]     GitHub Actions secret
  --gcp project[=SECRET_NAME]                GCP Secret Manager
  --render TEMPLATE=OUT                      rendered file
  --record-only                              record without pushing the value now

sec place APP_DB_PW --gh muthuishere/app:production --gcp my-project

sec rotate

New value → re-pushed to every recorded placement → the steps it cannot do are printed rather than assumed.

  --gen            generate the new value here (passwords you own, e.g. DB users)
  --len N          length for --gen (default 32)
  --no-symbols     for --gen
  --hook SCRIPT    run with SEC_NAME / SEC_NEW_VALUE / SEC_OLD_VALUE in the environment,
                   to apply the change at the source
  --undo           bring back the previous version and re-place it
  --purge          drop retired ciphertexts, after you revoked them upstream

sec rotate APP_DB_PW --gen --hook hooks/postgres-rotate.sh

The old version stays listed as "still to revoke upstream" until --purge. That is deliberate: sec will not mark a revocation done that it did not witness.

sec where

Every placement plus recent uses of a secret — the compromise-day question, in one command.

sec where APP_DB_PW

sec audit

Who used what, when. Never values.

  --name NAME      filter by secret
  --action A       filter by action (exec, run, set, rotate, …)
  --since 7d       window like 24h, 7d, 30d
  --retired        secrets with retired versions still to revoke upstream

sec ls · sec rm · sec get

sec ls [--tag t] [--json]    # names, version, placement count, last use, source — never values
sec rm NAME                  # delete a secret and its retired versions
sec get NAME --print         # owner-only, and denied at the harness for agents

sec identity

sec identity                              # which backend holds the key
sec identity move --to keyring|file       # switch; verifies the new location reads back
                                          # BEFORE removing the old copy
sec identity export --out FILE --confirm  # a backup for your password manager
sec identity import FILE

What the keyring buys you: no plaintext key on disk, so a disk image, a Time Machine backup or an rclone of the wrong directory doesn't carry it. What it does not buy you: it cannot stop a process running as you from asking the keyring. That exposure is identical to a 0600 file.

sec recipients

List or add age public keys that can decrypt the vault — how a teammate or a second machine gets in.

sec recipients
sec recipients --add age1…       # re-encrypts every secret

sec cert

Local TLS, with private keys written 0600 — because a dev certificate is a credential, and it usually ends up world-readable in /tmp.

sec cert ca                      # a local CA
sec cert issue --cn HOST         # issue from that CA
sec cert self-signed --cn HOST

sec skill install

Symlinks skills/sec into ~/.claude/skills/ and ~/.agents/skills/, and merges these into ~/.claude/settings.json permissions.deny:

Read(~/.config/sec/**)     # the vault and the identity
Read(**/.env*)             # the files sec writes for you
Bash(sec get:*)            # the print path
Bash(sec export:*)         # the bulk print path

So the harness refuses, not the model.

Threat model. sec defends against sloppiness and logs — secrets in transcripts, guides, commits, test output, chat. It does not defend against a hostile agent with network access: it could curl a value to a webhook through exec, and so could every other tool in this category. The refusal of output-only commands and the audit line for every use make the silly attempt visible, not impossible.
