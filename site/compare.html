the landscape, as of October 2026

Most of these are better than sec — at something else.

Secret management split into three jobs that people keep confusing: storing a secret for a team, injecting it into a process, and tracking every copy so you can rotate it. Nearly every tool is excellent at one or two. Here is where each actually lands.

the honest part

What the others do better.

pick Doppler / Infisical / Vault instead

When the secret belongs to a team, not a laptop

sec has no web dashboard, no project→environment hierarchy, no approval workflow, no RBAC, no audit console, no SSO, and sharing is "add an age recipient". For ten engineers and four environments, that is the wrong tool and you will feel it in week two. Vault additionally does the thing that beats every broker: dynamic, short-lived credentials — a secret that expires in an hour is better than a secret you carefully hid.

pick sec

When one person and their agents run everything

An operator with a dozen repos, a VPS, some cron jobs and three coding agents. The real risk isn't a rogue insider — it's a value that got pasted into a session and now lives in four files you'd have to grep for on a bad day. sec answers that with where, one binary, and no service to keep alive. It's a personal-infrastructure tool that is honest about being one.

not built yet

Where sec is behind, plainly.

01

No MCP server

sec reaches agents through a harness hook, sec agent and sec sh. An agent that only speaks MCP gets nothing from it yet.

02

Few cloud targets

Placements cover .env files, rendered files, paths, GitHub Actions, GCP Secret Manager, ssh hosts and containers. No AWS Secrets Manager, Vercel, Fly, Kubernetes Secrets or Azure Key Vault — Doppler's list is far longer.

03

No short-lived credentials

Every secret is static until you rotate it. Vault and Infisical can mint one that expires on its own, which beats hiding a long-lived one well.

04

The audit log is local

sec logs is one machine's history. There is no shared, team-wide log — for that, use a team tool (or vsync's bucket log for repo-scoped secrets).

the two real differences

Injection isn't the hard part any more. These still are.

01

Output redaction

Every tool here keeps the value out of the model on the way in. Almost none scrub it on the way out — and in an agent loop, output is input. A curl that echoes its own Authorization header, a framework that prints its DSN on a startup error, a test that dumps the config: the value re-enters the context through the result. sec scrubs stdout and stderr line-buffered, including base64, hex, URL-encoded and JSON-escaped forms.

02

The placement ledger

Storing a secret is solved. Knowing where all its copies are is not. Every sec write records a placement, so rotate replays them instead of relying on your memory — and prints what it cannot do itself, rather than pretending it's done. Nothing else on this list keeps an outbound copy ledger on the client. Since October 2026 the ledger reaches past the laptop: sec push writes files and whole folders into mounted volumes, ssh hosts and containers, and sec ok re-pushes any copy left on an old version.

Where the industry agrees: 2026's guidance from AWS and Auth0 converged on one rule — if you don't want an agent to leak a credential, don't give the credential to the agent; give it a broker and block the read path at the harness. sec implements exactly that rule, with the block as a permissions.deny entry rather than a cloud-specific hook. The disagreement is only about where the broker lives: their answer is a service, sec's answer is a 0600 file and a subprocess.
decision

Pick in one line.

team + envsInfisical (open source) or Doppler (fastest onboarding). Then use sec locally on top if you like.
enterpriseVault — for dynamic credentials and encryption-as-a-service, not for storing static ones.
git-ops configsops + age. It's the right shape for encrypted files in a repo, and sec doesn't try to replace it.
AWS-onlySecrets Manager with the agent deny hook. One cloud, one story, no extra tool.
you + your agentssec. Output redaction, argv and config files, a copy ledger that reaches servers and containers, no service to run.
repo + env, small teamvsync for the per-repo, per-environment vault; sec on top for agents and placements.
